皆様、ごきげんよう。

# 1. 要件定義（Requirements）

## **目的：どのような機能を持ったプログラムにするかを明確にする。**

まずは「何を作るか」を決めますの。ここが曖昧ですと、後で右往左往することになってしまいますわ。

- 対戦形式: ユーザー対コンピュータの1対1。

- 入力形式: 「グー、チョキ、パー」の文字列、または「1, 2, 3」の数字の両方を受け付ける。

- 勝敗ルール: 標準的なルールに基づき、勝ち・負け・あいこを判定する。

- エラー処理: 規定外の入力があった場合、優しくエラーを表示して再入力を促す。

- 戦績管理: ゲーム終了まで、累計の勝利・敗北・引き分け数を記録する。

- 継続機能: 1回ごとに「もう一度遊ぶか」を選択でき、終了時に最終戦績を表示する。

# 2. 設計の概要（Design）

## **目的：要件を実現するためのプログラムの構造を決める。**

次に「どう作るか」の設計図を描きますわ。

- **データ構造**:

  - 手の情報を辞書型（dict）で管理し、あらゆる入力を共通の数値（0, 1, 2）に変換して扱います。

  - 戦績保持用の変数（wins, losses, draws）を用意。

- **メインループ**:

  - while 文を使用し、ユーザーが「終了」を望むまでエレガントに繰り返します。

- **ロジック（勝敗判定）**:

  - random.randint でコンピュータの手を決定。

  - 以下の数式を用いると、if文を並べるよりスマートに判定できますわ。

    - 判定式: $(player\_hand - computer\_hand) \pmod 3$

    - 結果が 0 なら「あいこ」、1 なら「負け」、2 なら「勝ち」ですわ。

# 3. 実装（Implementation）

具体的なコードは main.py をご覧になってくださいまし。ここでは、美しく保守しやすいコードを書くための鉄の掟を伝授いたしますわ。

## 実装で意識すべきポイント

- **意味のある単位で関数を分ける**: 一つの関数に仕事をさせすぎないことですわ。

- **副作用のない関数を意識する**: 同じ入力を与えれば、必ず同じ結果を返す。これがテストを楽にする秘訣です。

- **変数には意味のある名前を付ける**: `a` や `x` ではなく、`user_choice` のように役割がわかる名前を付けるのが淑女の嗜みです。

- **マジックナンバーを避ける**: 唐突に現れる「3」などの数字は、定数（例：`HAND_COUNT = 3`）として定義しておきなさい。

## 具体例と理由

**悪い例**: `def check(h1, h2):`

- 何をチェックするのか、`h1`が何なのか不明ですわ。

**良い例**: `def determine_winner(player_hand, computer_hand):`

- 勝敗を決める関数だと即座に理解できますわね。

- **理由**: コードを読む時間は、書く時間の10倍以上と言われています。未来の自分や仲間のために、読みやすさを優先するのです。

# 4. テスト＆修正（Testing & Debugging）

実装したものが正しく動くか、厳しくチェックいたしますわ。

なぜ「良い設計」がここで活きるのか

- **副作用のない関数の恩恵**:
「この関数に0と1を入れたら、必ず結果は2になる」ということが独立して検証できるため、バグの特定が劇的に早くなりますわ。これをテストの容易性と呼びます。

- **修正のしやすさ（保守性）**:
関数が小分けにされていれば、一箇所を直した際に他の場所が壊れる「二次災害」を防げます。

- **再利用性**:
綺麗に分けられた関数は、他のプログラム（例：あっち向いてホイ）でもそのまま使い回せるかもしれませんわ。
